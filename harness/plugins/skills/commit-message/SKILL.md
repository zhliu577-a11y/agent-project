# 提交信息规范技能

当你被要求“写提交信息 / 生成 commit message / 帮我提交”时，按本技能执行。

## 格式

提交信息分两类：

- 简短提交（默认）：一行，结构为 `<type>: <一句话总结>`
- 复杂提交（改动多、跨模块）：一行标题 + 空行 + 要点列表正文

标题一行不超过 72 个字符。

## type 选择

| type | 何时使用 |
|---|---|
| `feat` | 新功能、新插件、新能力 |
| `fix` | 修复 bug |
| `refactor` | 重构，不改外部行为 |
| `docs` | 只改文档 |
| `chore` | 构建、依赖、CI、杂务 |
| `test` | 只改测试 |

## 语言与风格

- 本仓库用中文写一句话总结，格式：`<type>: 做什么（关键细节/范围）`；
- 动词开头（新增/修复/重构/接入/迁移），说“做了什么”，不说“做了什么吗”；
- 括号里放关键细节，例如：
  - `feat: 模型插件化（M2：plugins/model/deepseek + openai 示例，AGENT_MODEL 选择）`
  - `refactor: 插件目录 + MCP/Hooks 双网关架构（ADR 0001）`
- 正文要点以 `- ` 开头，每条一句话；
- 有对应 ADR 时在标题括号或正文里注明（ADR 编号）。

## 检查

写完后自检：标题是否说明“为什么/做了什么”、type 是否准确、
是否漏掉行为变化（如删除文件、配置项改名）、是否超过一行 72 字符。

## 边界

- 不编造未发生的改动：只总结实际 diff；
- 用户没让提交时，只输出提交信息文本，不执行 git 命令。
